# HydroDrop

A SwiftUI water-tracking app for iPhone, with widgets and an Apple Watch app. It uses
SwiftData with CloudKit for storage, StoreKit 2 for the HydroDrop+ subscription, and an
AdMob banner for free users. The deployment target is iOS 17, and the app is built with
Xcode 26/27. iOS 26-only APIs, such as FoundationModels for Say it, sit behind
`#available`.

## Building

- `HydroDrop.xcodeproj` is generated by XcodeGen from `project.yml` and is gitignored.
  Run `Scripts/generate.sh` after switching branches or adding files. Don't call bare
  `xcodegen`: the script also patches the scheme's StoreKit configuration, and without
  that patch the paywall comes up empty.
- XcodeGen picks up new folders under `HydroDrop/` on its own. No project edits needed.
- Xcode Cloud runs `ci_scripts/ci_post_clone.sh`. There is no GitHub Actions CI.
- Claude Code on the web runs on Linux, so it cannot build, run or test the app. Review
  changes carefully, and say plainly that they're unbuilt. Jonathon builds on his Mac.
- Releasing:
  - `Scripts/release.sh` handles `status`, `bump`, `archive`, `export` and `upload`.
  - `Scripts/preflight.sh` checks for past App Review rejection causes, including a bare
    ad `Request()`. Every ad request has to go through `AdManager.makeRequest()`.
  - Both stop before App Review submission, which is always done by hand.

## Working with Jonathon's Mac

- The main checkout is `~/Developer/HydroDrop`. Other sessions often work there with
  uncommitted changes, so don't have him switch branches in it. To try a branch, use a
  worktree:
  `git worktree add ../HydroDrop-<name> <branch>`, then `cd` in and run `Scripts/generate.sh`.
  If it can't find xcodegen, run `ln -s ~/Developer/HydroDrop/.tools .tools` first.

  phone, he has to pick his own device.
- Give him complete copy-paste command blocks.

## App structure

- **Navigation.** Two tabs: Today (`HomeView`) and History (`HistoryView`). Settings is
  not a tab. It is a sheet opened from the gear at the top right of both tabs; the gear's
  accessibility label is "Settings", and the UI tests rely on it.
- **`AppRouter`** (in `Notifications/WeeklyRecapNotifier.swift`) owns cross-screen
  navigation: `showingSettings`, `settingsIsOnScreen`, `pendingBottleTagID`,
  `pendingInsights` and `showingWeeklyRecap`.
  - An alert or sheet requested underneath a sheet, or while one is still dismissing,
    is dropped, not queued. So anything the root or Today presents must wait until
    `router.settingsIsOnScreen` is false. That flag is set in the sheet's `onAppear` and
    cleared in its `onDismiss`.
  - `RootTabView` closes Settings first when a bottle tag, the recap's Insights link or
    a recap notification arrives.
  - Never dismiss two stacked sheets in the same turn. See
    `WeeklyRecapView.onSeeInsights`, which waits for the recap to close before
    Settings closes.
- **Settings.**
  - `SettingsView.swift` is a short index of one-line rows, built with
    `SettingsRowLabel` and `SettingsIcon`. Each row shows its current value on the
    trailing side. The index also holds the HydroDrop+ card (`plusSection`) and the
    version footer; long-pressing the footer opens `EventCountsView`.
  - Detail pages live in `Views/Settings/`: Goal, Reminders, QuickAdd, Mascot,
    SmartFeatures and Health.
  - Put a new setting on its area's page. Add an index row only for a new area. Keep
    footers short, one per group.
- **HydroDrop+ gating.** Subscribers get the real control. Everyone else gets a locked
  row that opens `PaywallView(source:)`.
  - `PaywallSource` raw values are `EventCounter` keys, so renaming one resets its count.
  - Views check `StoreManager.isSubscribed`.
  - `EntitlementCache` is the one entitlement read that is safe off the main actor.
  - `AppSettings.*Active` combine a setting with that cached entitlement.
- **Settings storage and the widget.** `AppSettings` syncs most settings through
  `CloudSettingsStore` (iCloud key-value storage). The widget is republished when the
  goal, units or quick-add sizes change, from `HomeView.mirrorToCompanions`.

## Conventions

- Comments explain the reason behind the code in full sentences, often with the history
  ("used to…, which meant…"). Match that density and voice.
- Commit messages have an imperative subject and a prose body explaining the reason.
  Work lands on `main` through pull requests merged with a merge commit.
- The website is `docs/`, served at hydrodrop.us.

## Debug launch arguments (all compiled out of Release)

- `-UITestSeedHistory`: a fresh on-disk store with a seeded week of drinks. It also
  resets the cached entitlement, turns on `AppSettings.isScreenshotMode` and hides ads.
- `-UITestForceSubscribed`: forces HydroDrop+ on.
- `-UITestSkipOnboarding`: skips first-launch onboarding.
- `-SimulateBottleTap <url>`: simulates tapping an NFC bottle tag.
- World scene: `-WorldPreview <goal days> <vitality %>`, `-WorldTime dawn|day|dusk|night`,
  `-WorldWeather clear|cloudy|rain|snow` and `-WorldAllDecorations`. See `WorldDebug`.

Run on the Mac, from a checkout of the branch:

    Scripts/generate.sh
    SIM=$(xcrun simctl list devices available | grep -m1 "Pro Max" | sed -E 's/.*\(([0-9A-F-]{36})\).*/\1/')
    xcrun simctl boot "$SIM" 2>/dev/null
    xcrun simctl status_bar "$SIM" override --time 9:41 --batteryState charged --batteryLevel 100 --cellularBars 4 --wifiBars 3
    TEST_RUNNER_SCREENSHOT_OUTPUT_DIR="$PWD/screenshots" xcodebuild test -project HydroDrop.xcodeproj -scheme HydroDrop -destination "id=$SIM" -only-testing:HydroDropScreenshotUITests/ScreenshotUITests

### App Store images

The designed images have the 6.9-inch set in `screenshots/` and the 6.5-inch set in
`screenshots/6.5-inch/`. Each phone shows one raw capture:

| Image | Source |
|---|---|
| `01-hero` | none (no phone in this design) |
| `02-today` | `01-today` |
| `03-history` | `05-history-plus` |
| `04-skins` | `04-paywall` |

To rebuild one:
1. Scale the capture to cover the phone's screen area.
2. Paste it through an anti-aliased rounded-rect mask with corner radius 105.
3. Redraw the bezel's inner edge and the Dynamic Island on top in `#0C0C0E`.
4. Leave everything outside the screen untouched.

| Set | Canvas | Screen area | Dynamic Island |

| 6.9-inch | 1290×2796 | (218,824)–(1072,2682) | (536,856)–(756,920) |
